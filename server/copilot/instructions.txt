/* Copilot: Express Router to handle PayPal webhooks with verification.

Imports:
- Router from "express"
- prisma from "../db"
- { sha256, toCents } from "../utils"
- { getClient } from "../paypal"
- node-fetch (or global fetch) to call PayPal verify webhook signature API if SDK helper not present

IMPORTANT:
- Use express.raw({ type: "application/json" }) for this route so we can verify the signature with the raw body.

POST /api/paypal/webhook
Steps:
1) Read required headers:
   - paypal-transmission-id
   - paypal-transmission-time
   - paypal-cert-url
   - paypal-transmission-sig
   - paypal-auth-algo
2) Get PAYPAL_WEBHOOK_ID from env
3) Call PayPal verify endpoint /v1/notifications/verify-webhook-signature with:
   {
     auth_algo, cert_url, transmission_id, transmission_sig, transmission_time,
     webhook_id: PAYPAL_WEBHOOK_ID,
     webhook_event: <parsed JSON body>
   }
4) If verification_status !== "SUCCESS" -> return 400.

5) Handle event types:
   - "PAYMENT.CAPTURE.COMPLETED"
   - (optionally) "CHECKOUT.ORDER.APPROVED" or "CHECKOUT.ORDER.COMPLETED"

6) Extract:
   - resource.purchase_units[0].custom_id as clickId (affiliate click id)
   - resource.supplementary_data.related_ids.order_id (or resource.id)
   - amount.value (decimal string) and currency_code
7) Upsert Order by orderNumber = resource.id (or the order_id)
   - amountCents = Math.round(parseFloat(amount.value) * 100)
   - currency = currency_code
   - paidAt = now
8) If clickId present:
   - find Click by clickId; get its Affiliate and ratePct
   - commission = Math.round(amountCents * ratePct / 100)
   - create Attribution { orderId, affiliateId, clickId, commissionCents, ratePct, status: "pending" }
9) Return { ok: true }

Secure: no admin token; rely on PayPal signature verification only.

Export default router.
*/

Purpose: A concise, readable checklist and an expanded set of actionable todos to complete before
you (or I) push this PayPal affiliate integration into a production/staging environment.
Paste this in the repo so future sessions or maintainers can follow it step-by-step.

High-level goals before production:
- Ensure PayPal webhook signature verification is enforced (no dev bypass).
- Confirm webhook URL is registered with the correct `PAYPAL_WEBHOOK_ID` in PayPal dashboard.
- Ensure persistence is robust (move off JSON files to a DB for production).
- Add integration tests and monitoring; document runbook and rollback strategy.

Quick "readable" summary for humans:
1) Start your staging server and expose it publicly (ngrok or staging host).
2) In PayPal Developer Dashboard (Sandbox/Live), create or update a Webhook pointing at
   your `/api/paypal/webhook` endpoint. Copy the webhook id into your production environment
   as `PAYPAL_WEBHOOK_ID`.
3) Remove any dev bypass flags in production: `DISABLE_PAYPAL_WEBHOOK_VERIFY` must be absent
   and `NODE_ENV` must be `production`.
4) Run PayPal's "Send test event" (type `PAYMENT.CAPTURE.COMPLETED`) against the webhook URL
   and confirm your server logs show a successful verification and an attribution record.
5) Migrate JSON data to a proper relational DB and add a unique constraint on (`orderId`,`clickId`,`affiliateId`).

Detailed pre-production checklist (actionable, ordered):

1) Environment & secrets
   - Do NOT commit secrets to the repo. Store the following in your hosting provider's secret store:
     `PAYPAL_ENV` (sandbox|live), `PAYPAL_CLIENT_ID`, `PAYPAL_CLIENT_SECRET`, `PAYPAL_WEBHOOK_ID`,
     `COOKIE_SECRET`, and any encryption keys.
   - Set `NODE_ENV=production` on the host. Remove or *never set* `DISABLE_PAYPAL_WEBHOOK_VERIFY`.

2) Confirm webhook route uses raw body
   - Ensure in `server/index.js` the webhook route is mounted explicitly with `express.raw({ type: 'application/json' })`:
     `app.post('/api/paypal/webhook', express.raw({ type: 'application/json' }), paypalWebhookRouter)`
   - Verify `express.json()` is used for the rest of the app but does not intercept this route.

3) Register the webhook in PayPal
   - In PayPal Developer Dashboard, add a webhook URL for the appropriate environment.
   - Add only the event types you need (e.g., `PAYMENT.CAPTURE.COMPLETED`, `PAYMENT.CAPTURE.DENIED`, `PAYMENT.CAPTURE.REFUNDED`).
   - Save the webhook and copy the returned `webhook_id` into your production env as `PAYPAL_WEBHOOK_ID`.

4) Remove dev bypass & harden verification
   - Confirm code does not accept requests lacking PayPal signature headers in production.
   - If you used a development bypass (e.g., `DISABLE_PAYPAL_WEBHOOK_VERIFY`), ensure it's only allowed in local dev and the code requires both `NODE_ENV === 'development'` and the flag set to '1'.
   - Add a startup-time check that fails to start the server when `NODE_ENV === 'production'` and `PAYPAL_WEBHOOK_ID` is missing.

5) Test with PayPal
   - Expose the server publicly. With ngrok: `ngrok http 4000` (or your port). Ensure a single ngrok session for your account.
   - In PayPal dashboard, use "Send test event" with `PAYMENT.CAPTURE.COMPLETED` and the event body matching shape used in your code.
   - Check server logs for verification success and for the created Order and Attribution entries.

6) Idempotency & dedupe
   - Ensure `server/db.js#createAttribution()` is idempotent by unique key or pre-check.
   - Run `node server/scripts/dedupe-attributions.js` to dedupe historical JSON records.
   - When migrating to SQL, add UNIQUE(orderId, clickId, affiliateId) and use an upsert pattern.

7) Data migration & backups
   - Export `server/data/*.json` (orders, clicks, attributions) and keep a timestamped backup.
   - Add a migration script to import JSON into your chosen DB schema. Test migration on staging.

8) Tests & CI
   - Add unit tests for `verifyWebhookSignature()` (mock SDK + REST fallback), `createAttribution()` idempotency.
   - Add integration tests that simulate a raw PayPal webhook (use fixture bytes and headers) and assert database state.
   - Run tests in CI on PRs and before merges to master/main.

9) Logging, alerts & observability
   - Log verification failures with full headers + transmission_id (avoid logging secrets).
   - Save failed verification payloads to a retry queue / DB table for manual inspection.
   - Add monitoring/alerts (Sentry, Datadog, or similar) for repeated verification failures or sudden increases in voided attributions.

10) Post-deploy smoke tests & runbook
   - After deploy, run these steps:
     a) Send PayPal "Send test event" -> expect 200 OK and `{ok:true}` in response.
     b) Run a real sandbox purchase (create order -> approve -> capture) and verify an attribution is created.
     c) Verify refund/void flow: send a `PAYMENT.CAPTURE.REFUNDED` event and confirm attributions are voided.
   - If verification fails, follow rollback steps: disable webhook in PayPal dashboard, rollback code, and investigate logs.

11) Optional improvements (future tasks)
   - Add message queue for webhook processing to handle spikes and retries (e.g., RabbitMQ, SQS).
   - Add cryptographic idempotency keys (store PayPal transmission_id or event id) to prevent replay.
   - Harden self-referral checks and fraud detection (compare hashed emails, rate-limit affiliates, require payout verification).
